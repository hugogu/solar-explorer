# 太阳系 · Solar Explorer

**用真实星历驱动的交互式 3D 太阳系。**

行星、卫星、矮行星与彗星按各自真实的轨道运行、按真实的速率自转。把时间拨到任意时刻，
就能读出你所在地的日出时间、下一次日食，以及它的影子将在地面上扫过的轨迹。

## 这是什么

一个纯前端的单页网站：没有后端，也不请求任何天文接口。所有位置、自转角、升落时刻与
日食接触时刻都在浏览器里按公开的天文理论算出来，并有 112 个测试对照已公布的数值。

## 功能

### 完整的太阳系结构

八大行星、8 颗矮行星、29 颗主要卫星、8 颗著名彗星，以及带柯克伍德空隙的小行星带、
木星特洛伊群、柯伊伯带、离散盘和奥尔特云内缘标记。可以在**真实比例**（大部分是空旷的
虚空，本来就是如此）和**紧凑视图**之间切换；每一类天体都能单独开关显示。

<img src="docs/images/solar-system.jpg" alt="内太阳系与小行星带" width="100%">

### 任意时刻的真实位置

位置和自转角来自星历计算，不是动画循环。时间可正放、倒放，速度从实时到「10 年/秒」
共十档，也可以直接跳到某个日期。一旦离开行星根数的有效区间，时间栏会明确提示。

<img src="docs/images/jupiter.jpg" alt="木星的云带与木卫一、木卫二" width="100%">

### 日出日落与当地天象

选定地点后给出日出、上中天、日落、昼长、三种曙暮光、月出月落与月相，极昼极夜也会
正确标出。其他天体回答同样的问题：它的一个太阳日有多长（火星 24.66 小时、月球约
29.5 个地球日、水星 176 个地球日），以及站在它上面时太阳下一次何时升起。

<img src="docs/images/earth-night.jpg" alt="地球晨昏线、夜面城市灯光与大西洋上的太阳反光" width="100%">

*真实影像贴图是可选的。有它时，地球会带上日面影像、云层、夜面城市灯光，以及能反射
阳光的海面；没有它时，所有天体都回退到程序化生成的表面。*

### 日食月食，以及影子落在哪里

列出未来的日月食，给出类型、食分、各阶段时刻，以及**在你所选地点**实际能看到什么。
日食进行时，地表会画出真实宽度的食带，本影随时间沿食带移动，半影边界标出哪些地方
能看到偏食。表面的明暗由真实的视圆面几何逐像素计算，因此无论场景用什么比例绘制，
影子的大小都是对的——同一套代码也负责木卫一投在木星上的影子。

<img src="docs/images/eclipse-track.jpg" alt="2027 年日全食横穿北非的食带，本影位于利比亚上空" width="100%">

### 站到天体表面

站在地球、火星或月球表面抬头看。天空使用 Preetham 日光模型并旋转到当地天顶方向，
星星随太阳升高而隐没，视图会切换到真实比例，让日月的视直径与实际相同——你可以亲眼
看着刚刚从历表里读到的那次日出真的发生。

<img src="docs/images/sunrise.jpg" alt="从地球表面看到的黎明，木星与月球挂在地平线之上" width="100%">

### 桌面与移动端

桌面用鼠标与键盘，手机与平板用单指旋转、双指缩放；窄于 900 px 时界面自动折叠为底部抽屉。

### 中英双语

界面文字、读数，以及 54 个天体的完整词条——一句话简介、正文与冷知识——都有中英两版。
顶栏的切换按钮实时生效，时间、镜头与当前选中的天体都不会丢失，选择也会被记住。
首次访问依次按 `?lang=zh`、`?lang=en` 和浏览器语言判断。
数字也随语言变化：中文按万、亿分级（9.18 亿公里），英文按千分级（918 million km）。

## 快速开始

```bash
git clone https://github.com/hugogu/solar-explorer.git
cd solar-explorer
npm install
npm run dev
```

打开 <http://localhost:5173>。

可选：下载地球与月球的真实影像贴图（公有领域的 NASA 影像，经由 three.js 仓库分发）。
不执行也能正常运行——所有天体都有程序化生成的表面作为回退。

```bash
npm run fetch-textures
```

生产构建：

```bash
npm run build && npm run preview
```

## 精度与数据来源

计算全部在浏览器内完成，不请求任何天文接口。

| 项目 | 方法 | 与公布值的一致性 |
| --- | --- | --- |
| 太阳位置 | 截断 VSOP87D 地球级数 + FK5 修正 + 章动 + 光行差 | 二分二至时刻相差 1 分钟以内 |
| 月球位置 | 截断 ELP-2000/82（Meeus 第 47 章） | 完整复现例题 47.a |
| 行星位置 | JPL 主要行星近似轨道根数 | 1800—2050 年内约 1 角分 |
| 地球自转 | 视恒星时 + 岁差 + 章动 | 与升落计算一致到 0.02° |
| 其他天体自转 | IAU/WGCCRE 旋转要素（含月球天平动） | 度级 |
| 日出日落与曙暮光 | 对太阳高度求根 | 北京冬夏至与天文年历一致到分钟 |
| 日月食预报 | Meeus 第 54 章；本地环境由日月视圆面地平几何直接计算 | 食甚时刻相差 1 分钟以内 |
| 食带轨迹 | 逐点求解影锥轴与地球的交点；中心食时长直接测量 | 3% 以内 |
| 冲与合 | 对地心黄经差求根 | 火星 2027-02-19、木星 2027-02-11 |

几个可核对的实例（测试见 `tests/`）：

- **2027-08-02 日全食**：食甚点位于埃及 25.4°N 33.1°E，最长全食 **386 秒**（星表 383 秒），
  食带最宽 262 公里（星表 258 公里）。
- **2027-02-06 日环食**：最长环食 **471 秒**，星表 471 秒。
- **2030-11-25 日全食**：食带自南大西洋起，横穿南部非洲与印度洋，在昆士兰再次登陆。
- 2023—2027 年 15 次已公布日月食的日期、类型与食甚时刻。

### 已知的近似

这些在界面里也会明确标注，不做隐瞒。

- **轨道相位**：所有天体的轨道要素（半长轴、偏心率、倾角、周期）都是实测值。但只有
  行星、月球、彗星（锚定在实测的近日点通过时刻）和木星的四颗伽利略卫星，其历元相位
  是真实星历值。其余卫星与矮行星的相位为估计值，因此它们**在轨道上的具体位置**只是示意。
- **食带宽度**：未做月面地形改正。掠入射的日食本身"宽度"定义就不唯一，本站给出的横向
  宽度会明显大于星表值；但中心食时长仍在 3% 以内。
- **小天体群**：小行星带与柯伊伯带是按真实轨道分布统计生成的群体，不对应真实编号天体。
- **地球轨道线**画的是**地月质心**轨道，而地球本身绕质心摆动 ±4670 km，所以地球会
  偏离自己的轨道线几个像素——这是真实的。

## 项目结构

```
src/
  astro/    纯计算：时间尺度、坐标系、轨道、太阳、月球、行星、
            自转、升落、日月食、食带轨迹、银道坐标
  data/     天体目录：物理与轨道参数、科普内容
  i18n/     语言选择与界面文案表
  app/      模拟状态、时间控制、应用状态、日食监视
  render/   three.js 场景：天体、轨道、星空、小天体群、相机、程序化贴图
  ui/       界面面板（原生 DOM，无框架）
tests/      对照公布值的验证测试
scripts/    可选的贴图下载脚本
```

两条约束支撑着整个设计：

- `src/astro/` 既不 import three.js 也不碰 DOM，因此可以直接在 Node 中运行和测试。
- 渲染层不做任何天文计算，只消费 `Simulation` 给出的位置与姿态。

译文有意分成两种存放方式。界面文案放在键值表里（`src/i18n/strings.ts`），因为同一句话会被多个面板复用，
而且 TypeScript 能据此证明没有漏掉任何一个 key。天体词条则以 `Localised<T>`（`{ zh, en }` 并排）
直接写在数据文件中，这样同一个天体的两种语言会被一起审阅，不一致一眼就能看出来。

场景单位为 1 单位 = 1000 km。星历使用黄道坐标系（+Z 指向黄北极），three.js 是 Y 轴朝上，
因此 `(x, y, z)` 映射为 `(x, z, -y)`。

## 开发

```bash
npm run dev              # 开发服务器
npm test                 # 112 个对照公布值的测试
npm run lint             # eslint
npm run build            # 类型检查 + 生产构建
npm run fetch-textures   # 可选的真实影像贴图
```

`AGENTS.md` 记录了开发中花时间才弄明白的坑：自定义材质在对数深度缓冲下需要哪些 shader
chunk、相机为什么必须在任何投影之前发布自己的矩阵、判定中心食为什么必须用几何条件而不是
遮挡比例阈值，等等。

## 参与贡献

欢迎 issue 和 pull request。提交前有两点值得知道：

1. **跑一遍测试。** 它们对照的是已公布的数值——Meeus 例题、天文年历的升落时刻、日月食
   星表——而不是快照。失败通常意味着真的算错了，而不是需要更新基准。
2. **对近似要说实话。** 如果某个改动用精度换观感，请在代码里写清楚，并在界面上如实标注。
   这个项目的价值在于它给出的数字可以被信任。
